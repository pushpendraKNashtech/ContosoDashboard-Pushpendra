# Data Model: Document Upload and Management

## Document

Represents one uploaded file and its searchable metadata.

| Field | Type/constraint | Rules |
|---|---|---|
| DocumentId | integer key | Generated by the database; consistent with existing entities. |
| Title | required string, max 255 | Required for create/update; trim whitespace. |
| Description | nullable string, max 2000 | Optional; preserve null/empty semantics consistently. |
| Category | required string, max 100 | One of Project Documents, Team Resources, Personal Files, Reports, Presentations, Other. |
| Tags | nullable string, max 1000 | Optional normalized tag representation; search must be deterministic. |
| OriginalFileName | required string, max 255 | Display/download metadata only; never used as a storage path. |
| FilePath | required string, max 1000 | Relative generated path; unique GUID component; never exposed as a client-controlled path. |
| FileType | required string, max 255 | Validated MIME type/allow-list value. |
| FileSizeBytes | required long | Greater than zero and no more than 26,214,400 bytes. |
| UploadedDate | required UTC datetime | Set by the service, not the client. |
| UploadedByUserId | required integer foreign key | Must reference an authenticated user. |
| ProjectId | nullable integer foreign key | If set, uploader must be project manager or member according to the upload policy. |
| TaskId | nullable integer foreign key | If set, task must be visible to the requester and its project association must be respected. |
| UpdatedDate | required UTC datetime | Set by service on metadata or file replacement changes. |

### Document State

- **Pending**: in-memory workflow only; not visible to users.
- **Scanning**: file has passed basic validation and is awaiting malware result.
- **Available**: content and metadata are persisted and authorized users may access it.
- **Deleting**: cleanup workflow is in progress; it must not be treated as available.
- **Deleted**: metadata and content are removed permanently; retained audit records may reference the former document identifier without exposing content.

The persistent model should not expose pending or deleting records as available results. Failed uploads must clean up storage and avoid a usable metadata record.

## DocumentShare

Represents an explicit share from a document owner to a user or team.

| Field | Type/constraint | Rules |
|---|---|---|
| DocumentShareId | integer key | Generated by the database. |
| DocumentId | required foreign key | References an existing document. |
| SharedWithUserId | nullable foreign key | Set for a user-specific share. |
| SharedWithDepartment | nullable string, max 100 | Set for a team/department share when applicable. |
| SharedByUserId | required foreign key | Must be the owner, project manager, or administrator allowed to share. |
| SharedDate | required UTC datetime | Set by the service. |
| IsActive | required boolean | Allows revocation without granting access after revocation. |

At least one recipient target must be set. A user-specific and department/team share must not both be ambiguous for one record. Duplicate active shares for the same document and recipient must be prevented.

## DocumentActivity

Immutable audit event for document operations.

| Field | Type/constraint | Rules |
|---|---|---|
| DocumentActivityId | integer key | Generated by the database. |
| DocumentId | required integer | Retain identifier for audit correlation without requiring file availability. |
| UserId | required integer | Actor; must come from the authenticated request. |
| Action | required string | Upload, Download, Preview, Replace, MetadataUpdate, Delete, Share, or RevokeShare. |
| OccurredDate | required UTC datetime | Set by the service. |
| Details | nullable string, max 2000 | Must not contain file contents, secrets, or unnecessary personal data. |

Audit records are append-only for application users. Administrators may query reports but may not alter activity history through the feature UI.

## Relationships

- `User 1 -> many Document` through `UploadedByUserId`.
- `Project 1 -> many Document` through optional `ProjectId`.
- `TaskItem 1 -> many Document` through optional `TaskId`.
- `Document 1 -> many DocumentShare`.
- `User 1 -> many DocumentShare` as recipient and as sharing actor.
- `Document 1 -> many DocumentActivity`.
- `User 1 -> many DocumentActivity` as actor.

## Authorization Rules

- Owners may view, edit metadata, replace, delete, and share their documents.
- Project managers may manage documents associated with their projects.
- Project members may view/download project documents while membership remains active.
- Explicit share recipients may view/download shared documents while the share remains active and the account remains valid.
- Administrators may view, manage, and report on all documents.
- Employees may upload personal documents and project documents only in authorized project contexts.
- Search, preview, download, and report queries must apply the same authorization scope as their corresponding action.

## Indexes and Constraints

- Index `UploadedByUserId, UploadedDate` for My Documents and recent uploads.
- Index `ProjectId, UploadedDate` for project documents.
- Index `Category, UploadedDate` for filtering.
- Index `FileType, UploadedDate` for reports.
- Index `DocumentShare` by document and active recipient.
- Index `DocumentActivity` by document, user, action, and date.
- Enforce unique generated `FilePath` values.
- Add foreign-key delete behavior that prevents accidental cascade deletion of user/project records into audit data; document deletion must be an explicit service workflow.
